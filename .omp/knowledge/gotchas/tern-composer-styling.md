# Styling omp's composer from a Tern plugin (Tern 0.9.21, omp 18.20.2)

- An extension marks text for a plugin sheet through `Editor.describeDecorations` ranges `{from,to,s,fx}`. Tern turns known `s` tokens into `.sf-t-<token>` and `fx` into `.sf-fx-shimmer` / `.sf-fx-pulse` on the same span; unknown tokens are dropped. Spellbook keys on the pair `accent mono` (omp never emits it in the composer; `mono` draws nothing visible).
- omp memoizes decorations per text plus a generation; call `editor.invalidate()` when non-text state (casting, Reduce Motion) changes what they should be.
- Composer DOM: card `.sf-col[data-role^='omp.editor']` (`omp.editor.bash` in shell mode), row `[data-role='omp.composer.line']` holding the bash chip `[data-role='omp.composer.mode']` then `.sf-editor`. `:has()` works (0.9.14+, docs say otherwise). omp's own sheet uses `::before/::after` on the card, so put a chip on the line row's `::before`.
- Tern's composer shimmer (`.sf-editor .sf-fx-shimmer`) is a fixed rainbow, not the theme accent; override `background-image` only to recolour it.
- Check the live DOM in a headless window: `tern serve --control <port>`, then `tern ctl --control <port> css <name> <file>` to load a sheet (headless loads no plugins), `tree SEL` / `dump SEL` for classes and colours, `freeze-anims` + `motion-at MS` + `shot` to compare animation phases, `reduce-motion on`, `theme dark "<omp theme id>"` (ids like `amethyst`, `dark-gruvbox`). A Python socket client (one JSON line per command) is far faster than one `tern ctl` process per keystroke.
- `tern serve` started as a supervised service can die at once with a port clash; pick another port.
